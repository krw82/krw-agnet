# Engine v2 — 자율 인사이트 엔진 설계 (제한 해제 × 교차 평면 × 리포트 생성)

- 날짜: 2026-08-31
- 상태: 사용자 목표 확정 (품질 최우선, 제한 해제, GLM-5.3 테스트 — 완벽할 때까지)
- 근거: 엔진 제한 인벤토리 감사(2026-08-31, 파일:라인 실측) + P3 v3 스펙(D11~D14)
- 관련: 2026-08-30-openbb-observation-chain-design.md (P1~P3), D12와 동일 계열(자율성=어떻게, 규율=무엇을)

## 1. 목표와 불변식

**목표**: 사용자가 대충 물어도 — ① 온톨로지와 OpenBB/관측 데이터를 **유기적으로 교차 탐색**하며(한 평면 결과가 반대 평면 조사를 유발), ② 도구 호출·토큰·시간 제한 없이 충분히 깊이 연구하여, ③ 다각 관점의 **인사이트 + 보고서/위젯/차트**를 산출하는 엔진.

**불변식 (해제 대상 아님 — 인벤토리 EVIDENCE-DISCIPLINE 분류)**:
- 근거 교리: 강한 주장은 추적 가능한 직접 근거에만; 관측/advisory는 `strong_claim_allowed: false`; `grade_never_upgrades_directness`
- 밴더 중립, 답변 라벨(보도/관측 기준), 파일링 ladder 의무
- `state_precedes` 순서 게이트(context→targeted, search→brief, list→context), 투영 검증기, 새니타이저 claim↔ledger 바인딩
- 인프라 안전(유지·감시자화): MCP at-most-once, 풀 상한, 페이로드 상한(8MiB/16MiB), lease 갱신

## 2. 실증된 위험 → 설계 응답 (깨지는 순서의 역순으로 해제)

| # | 인벤토리 발견 (깨지는 순서) | 설계 응답 |
|---|---|---|
| R1 | 회복: `provider_episodes>256`/`actions>512` 시 클레임 거부 → 장기 런은 데몬 재시작 후 **영구 회복 불능** (0001_agent_v1.sql:617) | **E2 회복 재유도**: 카운트 상한을 바이트 기반으로 재정의(아티팩트·액션 청크 참조 방식), 상한 도달 시 "분할 체크포인트" 생성. 선행 조건 — 모든 제한 해제 전에 착공 |
| R2 | 작성기: 단일 compose 턴 16k 출력, 섹션 16/클레임 64/차트 3 상한 → **더 깊은 연구가 같은 구멍으로 압축됨** (수확 안 보임) | **E1 출력 표면 확장(최우선)**: 리포트 상태 머신(섹션 단위 다중 compose→verify 사이클), AnswerBundle v5(섹션 지속화 아티팩트), 차트 상한 완화(≤12)+종류 확장(카드가 이미 지원하는 area/scatter/waterfall) |
| R3 | 컨텍스트: 168k input 봉투, 80% 도달 시 강제 compose(9턴 런이 이미 158,875 input 소진 — 2026-08-28 리밸런스 기록) | **E3 예산→감시자**: 4개 `should_finalize_for_output_reserve` 트리거를 "새 턴 시작 정지 + 진행 중 완결"로 전환; 컴팩션 루프를 탈출 밸브가 아니라 **1차 메커니즘**으로; unlimited 프로파일(GLM 장기 컨텍스트 활용, 점진 상향 168k→320k→640k with 매트릭스 게이트) |
| R4 | 테스트 루프: 40분×18케이스≈6시간/패스, 매트릭스 타임아웃 상한 1800s, 채점은 `manual_review_required` | **E6 테스트 재구축**(아래 §5) |
| R5 | 비용: 턴당 96-144s, 사용량 3-6× 폭증 | 오픈소스·품질 우선 원칙으로 수용; `runs.usage`에 이미 기록됨 — 런별 리포트로 모니터링만 |

**3대 미지 → 실험 프로토콜로 전환**:
- 스톱 드리프트(프롬프트 스톱이 커널 몰수 없이 작동하는가) → E4의 단계별 매트릭스로 측정, 커널 백스톱(duplicate fingerprint, no_positive_value)은 유지
- 교차 평면 의무 중복(코스메틱 재질의 폭주) → 의무 지문(dedup)을 ladder-hint 패턴에 추가
- advisory 오염(ledger 3배에서 새니타이저 버티는가) → E6 채점에 "근거 다양성" 지표 추가

## 3. 교차 평면 유기 탐색 (E5) — 실증된 슬롯에 얹기

커널 `model_visible_capability_result` + `commit_research_result` 슬롯(ladder-hint 29ad96b와 동일 경로)에:
1. **관측→온톨로지**: planner가 `MarketSeriesV1`/`MacroSeriesV1` ingest 분기(현재 부재)를 가져 해당 시리즈의 티커·팩터로 `exact_precise_query_candidates`에 타겟 질의 의무 추가 + 커널 `kernel_cross_plane_hint`(자기소거, 지문 중복 제거)
2. **온톨로지→관측**: `ExternalFactorExposure.factor` 결과가 macro 팩터와 만나면 `krw_macro_series`/openbb 조회 의무 힌트
3. **openbb-mcp 엔드포인트**(P3 산출물 1번을 E5의 전제로 앞당김): 6단계 체크리스트로 바인딩, advisory 등급. 새 워크플로우 상태(openbb.* capability) 필요 — 상태 없으면 광고 불가 구조
4. 프롬프트 의무: 5개 analyst 프롬프트에 "힌트는 열린 의무" 문단(ladder와 동일 문형)
5. 대충 묻는 질문: orient 단계에서 **가설 트리 생성**(파일링·관측·openbb 3평면을 잇는 2-4개 가설)을 플래너 의무화 — `research_kernel`의 기존 obligation 구조 재사용

## 4. 제거 순서 (단계 = 게이트, GLM-5.3 매트릭스 녹색이 다음 단계 조건)

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **E1 출력 표면** (먼저) | 리포트 상태머신(다중 compose), AnswerBundle v5(섹션 지속화), 차트 ≤12·종류 확장, `MAX_ANSWER_SECTIONS` 16→64 | 장기 리서치가 16k를 넘는 리포트를 무손실 산출; 새니타이저 다운그레이드 0 |
| **E2 회복 재유도** | 에피소드/액션 상한 바이트 기반화 + 분할 체크포인트 | 60턴 모의 런 중 데몬 재시작 → 정상 재개 실증 |
| **E3 예산→감시자** | output-reserve 4트리거 전환, deadline lease 갱신형, unlimited 프로파일(점진 상향) | 40분 초과 런이 fallback 아닌 정상 완결; 컴팩션이 주 메커니즘인 매트릭스 |
| **E4 자율 스톱** | max_visits·action_limits max_calls 단계 해제(먼저 상향 3×→10×→무제한), 프롬프트 스톱 재설계(8슬롯 체크리스트 품질 게이트화) | 동일 질문에서 과잉연구(사소한 질문 60턴)·조기종료 모두 0; `state_precedes`·규율 회귀 녹색 |
| **E5 교차 평면** | §3 전체(openbb-mcp 바인딩 선행) | "CPI 서프라이즈→금리→관련기업→실적 근거" 자율 탐색 골든 케이스 통과(개입 없이) |
| **E6 테스트 재구축** | §5 | 매 패스 자동 채점 리포트 |

## 5. GLM-5.3 품질 루프 (E6)

- 매트릭스 확장: 타임아웃 1800→7200s, 병렬 유지, 케이스 3버킷(사소한/보통/심층 — 심층은 자율 리서치 전용 신설)
- **자동 채점 3축**(현 manual_review 대체): ① 근거 무결성(환각 0 — 기존 기준 유지) ② **근거 다양성**(파일링 direct + 관측 advisory + openbb 참조의 혼합 비율 — 교차 평면이 실제로 쓰였는가) ③ 완결성(8슬롯 체크리스트 충족률 + 인사이트 서술 존재)
- 정지 조건: 전 케이스 3축 녹색 2회 연속 — "품질이 완벽해질 때까지"의 조작적 정의
- 회귀: 기존 semantic eval v2(정확히 3개 후속질문 등)는 E1에서 리포트 형태가 달라지는 만큼 **버전 갱신(v3)** — 결론 우선·후속질문 규칙은 유지하되 리포트 가변 길이 허용

## 6. P1~P3와의 관계

- P1(진행 중: B6 리뷰→B7→B8, 패리티 게이트)은 그대로 완결 — E계열의 데이터 기반
- D13/D14(시세 상시등록 폐지, 발표빈도 필터)는 B8 전 소규모 태스크로 반영
- E5의 openbb-mcp 바인딩은 P3 산출물 1번을 앞당겨 수행(E5 전제)
- 순서: P1 완결 → E1→E2→E3→E4→E5→E6(각 게이트 통과 시 다음) — 단 E6 채점기는 E1과 병행 개발(E1 산출물 검증에 필요)

## 7. 리스크 기록

- 스톡 드리프트 실패 시 폴백: E4를 "무제한"이 아니라 "큰 상한(예: 턴 60)"에 머물고 품질 게이트만 무제한화 — 품질 목표는 동일 달성
- GLM 장기 컨텍스트에서의 컴팩션 품질 자체가 미검증 — E3에서 컴팩션 정확도 별도 측정
- 비용·시간 수용은 사용자 방침이나, 매트릭스 6시간/패스는 개발 속도 병목 — 심층 케이스 야간 배치 + 스모크 서브셋 주간 운영

## B. 축 1 — 심도(자율성): E1-E6 기존 스펙 + 업데이트 2건

E1 출력표면 → E2 회복 → E3 예산→감시자 → E4 자율스톱 → E5 교차평면 → E6 테스트 재구축
(각 단계 GLM-5.3 매트릭스 녹색이 다음 게이트). 상세는
`docs/superpowers/specs/2026-08-31-engine-v2-autonomy-design.md` 참조. 여기서는 이번 조사로
**스펙에 반영할 업데이트**만 기록한다.

**업데이트 1 — E5의 전제가 이미 완료됨.** 스펙 §3.3은 "openbb-mcp 엔드포인트 바인딩(6단계
체크리스트)이 E5의 전제"라고 썼으나, 샌드박스에서 바인딩을 완료했다(프리플라이트 4 엔드포인트).
E5의 실질 남은 과제는 ① 플래너 도달 게이트(research_action 개방 정책) ② `kernel_cross_plane_hint`
(관측↔온톨로지 상호 유발) ③ orient 단계 가설 트리(3평면을 잇는 2-4 가설)뿐이다.

**업데이트 2 — 게이트 메커니즘 통합.** openbb 도달 게이트는 이벤트 사다리 후보3(승인 대기,
"assess 턴 입력 삽입 힌트")과 동일한 메커니즘으로 설계한다. 하나의 "ladder-hint" 패턴으로
두 함정(8-K 이벤트 맹목 · 시세/거시 맹목)을 함께 해제 — 구현 1회, 효과 2배, 과설계 방지.
스펙의 골든케이스("CPI 서프라이즈→금리→관련기업→실적 근거" 자율 탐색)가 이 게이트의
완료 기준 그대로다.

## C. 축 2 — 접점: 워크스페이스 계약 번역층 (신규 축, 4레포 학습)

엔진은 소스(상태·근거·시각화)를 제공하고, krw-agent-service가 openbb-ai SSE로 번역한다.
엔진 코어를 건드리지 않는 순으로 정렬:

1. **reasoning_step 진행 표시** — 실엔진 런이 10-20분인데 지금은 완성 마크다운만 마지막에
   흐른다. 최소형: 게이트웨이 런 뷰에 진행 스냅샷(엔진 상태머신 단계 + provider_turns +
   직전 능력명) 추가 → 서비스가 폴링해 `copilotStatusUpdate`로 번역. 10-20분 대기가
   "지금 8-K 후보 조사 중(턴 5/…)"로 바뀐다. (최우선 UX 항목)
2. **인용 연동** — final_output의 근거를 `copilotCitationCollection`으로. 워크스페이스가
   렌더하는 source_info.type은 widget/web/artifact/direct retrieval뿐(Rita도 document→web
   매핑) → 공시 근거는 SEC URL을 `web`로 매핑하면 클릭 가능 인용이 된다. PDF 하이라이트
   좌표(quote_bounding_boxes)는 향후 확장.
3. **차트/테이블 아티팩트** — `final_output.visualizations`를 `copilotMessageArtifact`
   (chart 5종/테이블)로 변환하면 워크스페이스 채팅 안에 인라인 렌더. E1 Task 7(차트 3→12,
   종류 확장)과 정합 — E1 산출물이 곧 접점 자산.
4. **prompt_suggestions** — 후속 질문 제안. eval v3의 "정확히 3개 후속질문" 규칙과 같은
   소스에서 생성.
5. **위젯 컨텍스트 수용** — `widget-dashboard-select: true` 전환. 사용자가 대시보드에 올린
   openbb 위젯 데이터가 QueryRequest.widgets로 들어오면 이를 **advisory 관측 입력**으로
   엔진에 주입(강한 주장 금지 라벨 유지 — 엔진의 advisory 체계에 그대로 합류).
   "메인은 openbb, 엔진은 코파일럿 브레인" 구상의 정확한 접점.
6. **feedback 엔드포인트** — 업/다운 + trace_id 수집(공식 예제 42번 패턴). 답변 품질
   스레드의 실사용자 평가 데이터가 된다.
7. **(장기) 멀티에이전트 위임 수신** — 워크스페이스 오케스트레이터가 `assign_tasks_to_agents`
   로 krw에 위임할 때 `last_message.role=="ai" && agent_id=="openbb-copilot"` 패턴을
   감지해 조사 폭을 좁혀 응답(공식 예제의 위임 감지 관례).

## D. 축 3 — 폭: 기능 풍부화

**데이터 평면 확장 (openbb 큐레이션 3 → N)** — 채택 기준: ① 온톨로지가 못 주는 것
② 증거 교리와 등급(advisory vs filing-direct)이 명확한 것. 후보: 뉴스 센티먼트, 이코노믹
캘린더, ETF 플로우, 내부자 거래, 배당, 피어 세트. 각 도구는 오늘 검증한 패턴의 반복이다:
계약 2쌍(model/physical) + agent.yaml 등록 + 프리플라이트 핀 + (이번 배움) bare-hex 핀·
실제 release hash·readiness 문서·CA:TRUE. **반복 가능성 자체가 이번 스파이크의 최대 자산.**

**관측 평면** — P1 번들(B시리즈, 원본 반영 승인 대기)로 확충 완료 상태. D13/D14(시세 상시등록
폐지, 시드 ≥주간 발표) 정책과 정합 유지.

**워크플로우 신설 후보** (E4 자율스톡 안정 후 착수): 정기 모니터링(watchlist 스케줄 —
자율성 목표 /goal과 직결), 비교 리서치(A vs B — peer 세트 도구와 세트), 포트폴리오
코멘터리(공식 예제 99번처럼 위젯 데이터 + 엔진 근거 결합).

**산출 형식** — E1 리포트 상태머신(다중 compose→verify)이 안정되면, 리서치 결과를
워크스페이스 위젯으로 게시(create_widget 브리지 — 접점층 경유). "조사 결과가 채팅 로그에
묻히지 않고 대시보드에 자산으로 남는" 경험. 엔진이 브라우저를 조작하는 게 아니라
서비스가 게시 요청만 내보내는 것.

## E. 과설계 금지 — 하지 않을 것 (명시 목록)

1. **범용 코파일럿화 금지** — 위젯 SQL 분석, 대시보드 편집 16옵, 브라우저 브리지는
   워크스페이스/Rita의 영역. krw가 재구현하면 층위 충돌로 둘 다 서투른 게 된다.
2. **자체 임베딩 RAG 금지** — 엔진에 온톨로지 SQL+trace 체인이 있다. 문서 RAG가 필요하면
   관측 평면에서 openbb 컴패니언 MCP(query_documents)를 소비한다.
3. **멀티 LLM 오케스트레이터 금지** — GLM 단일 유지(비용·품질 루프 단순). 계약이 벤더
   중립이라 교체 가능성만 확보돼 있다(Anthropic 레이어 병합 사례).
4. **마이크로서비스 분해 금지** — 단일 엔진 + capability 사이드카 + 게이트웨이 토폴로지
   유지. 분해는 관측·배포 비용만 늘린다.
5. **만능 게이트 금지** — 힌트 게이트는 ladder-hint 패턴 하나로 통일(업데이트 2).
   플래너 정책의 종류를 늘리지 않는다.
6. **판단 기준(모든 신규 기능에 적용)**: "추적 가능한 근거를 늘리는가, 또는 사용자 질문
   커버리지를 넓히는가" — 아니면 하지 않는다.

## F. 장기 최선의 아키텍처 원칙 (유지·강화)

- **계약 우선**(69 descriptors) + 봉인 릴리스 + 프리플라이트 — openbb 편입이 이 사이클의
  재현성을 실증했다. 신규 능력은 전부 이 관문을 통과한다.
- **단일 증거 교리**(advisory 강한주장 금지, grade_never_upgrades_directness) — 데이터
  평면이 넓어질수록 이 교리가 차별점이 된다(4레포 어디에도 없는 것).
- **게이트 기반 해제** — E1→E6 순서, 매트릭스 녹색 조건 유지. "완벽할 때까지"의 조작적
  정의 = 3축 자동 채점(근거 무결성·근거 다양성·완결성) 2회 연속 녹색.
- **관측** — 런별 usage 이미 기록(runs.usage). Rita의 turn_usage 교훈(재POST마다 입력
  토큰 증가가 실제 비용)은 우리가 게이트웨이 단일 런 구조라 자동으로 회피.
- **하네스 부채 상환** — 엔지니어링 리뷰 7건 중 mock SSE e2e 0건, 취소 미중단 등은
  E6 테스트 재구축과 병행 상환.

## 리스크 기록

- 접점 번역층(krw-agent-service)이 얇은 스크립트로 남으면 계약 진화(openbb-ai 4개월
  메이저)를 못 따라간다 — openbb-ai 버전 고정 + 신기능 getattr 방어는 필수.
- 진행 스냅샷 노출이 엔진 내부 상태 과다 노출로 변질되지 않게 "단계+턴카운트+직전 능력명"
  3필드로 봉인.
- 게이트 해제 후 어드바이저리 데이터 오염(ledger 3배)은 E6 "근거 다양성" 지표가 감시 —
  스펙 §2의 3대 미지 프로토콜 그대로.

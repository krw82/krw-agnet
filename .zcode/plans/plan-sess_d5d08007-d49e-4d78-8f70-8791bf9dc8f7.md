# Ontology 스키마 자동 주입 설계 (수정본)

## 핵심 전제 (사용자 확인)
- 이 프로젝트의 모든 에이전트는 KRW ontology와 **세트** — ontology 없이는 의미 없음
- 따라서 `agent-image` 빌더가 ontology에 의존하는 것은 **자연스러움**
- `~/krw-ontology` 원본은 **읽기 전용** (수정 없음)

## 방식: `agent-image` 빌더에 ontology 스키마 생성 통합

`agent-image` 빌더가 `agent.yaml`의 prompt segment 중 하나가 `ontology_schema` 타입이면, ontology YAML에서 직접 prompt blob을 생성.

### 작업 1: PromptSegmentSource에 `ontology_schema` 필드 추가

`crates/agent-image/src/lib.rs` 수정:
```rust
pub struct PromptSegmentSource {
    pub id: String,
    pub path: Option<String>,           // 기존 path → Option으로
    pub ontology_schema: Option<OntologySchemaSource>,  // 신규
    pub stable_prefix: bool,
    pub private: bool,
}

pub struct OntologySchemaSource {
    pub root_env: String,    // "KRW_ONTOLOGY_ROOT"
    pub schemas: Vec<String>, // ["metric_dictionary", "quote_types", "claim_types", ...]
}
```

`agent.yaml`에서 선언:
```yaml
prompt_segments:
  ...기존 항목들...
  - { id: ontology_catalog, ontology_schema: { root_env: KRW_ONTOLOGY_ROOT, schemas: [metric_dictionary, quote_types, claim_types, risk_categories, objects] }, stable_prefix: true, private: true }
```

### 작업 2: compile_agent_dir에서 ontology YAML → Markdown 생성

`compile_agent_dir`의 prompt segment 루프(1664-1691) 수정:
- `path`가 있으면 기존대로 파일 읽기
- `ontology_schema`가 있으면:
  1. `root_env` 환경변수에서 ontology root 경로 확보
  2. 선언된 schema YAML들을 읽음
  3. 각 스키마에서 AI 관련 정보만 추출하여 Markdown 생성
  4. 생성된 Markdown을 prompt blob으로 intern

생성되는 Markdown 내용:
- **Metric 카탈로그**: 식별자, 표시명, 공시 별명(aliases), 설명 (metric_dictionary.yaml)
- **검색어 힌트**: quote_type별 ai_guidance (quote_types.yaml)
- **근거 유형**: claim_type별 설명과 예시 (claim_types.yaml)
- **리스크 분류**: 6개 카테고리 (risk_categories.yaml)
- **객체 타입**: 검색 결과 객체 목록 (objects.yaml)

### 작업 3: KRW_ONTOLOGY_ROOT 필수화

`compile_agent_dir` 시작 부분에서:
- agent.yaml에 `ontology_schema` segment가 하나라도 있으면 `KRW_ONTOLOGY_ROOT` 환경변수 필수
- 없으면 ontology 없이도 빌드 가능 (ontology 독립 agent 대응)

### 작업 4: Rust 검증 로직에도 같은 YAML 주입 (krw-contracts/build.rs)

`crates/krw-contracts/build.rs` 신규 생성 (research-planner/build.rs와 동일 패턴):
- `metric_dictionary.yaml` → `RESEARCH_PROPOSAL_V4_METRICS` const 자동 생성
- `objects.yaml` → `ALLOWED_OBJECT_TYPES` const 자동 생성
- 기존 하드코딩 `RESEARCH_PROPOSAL_V4_METRICS` (krw-contracts/src/lib.rs:122-148) 제거

### 작업 5: agent.yaml + SKILL.md 업데이트

- `ontology_catalog` segment를 planner, analyst, composer role의 prompt_segments에 추가
- SKILL.md에 "리서치 전에 ontology catalog를 읽어 사용 가능한 metric, 검색어, 근거 유형을 파악하라" 지시

### 작업 6: start_local_agent_gateway_stack.sh 업데이트

`image build` 전에 `KRW_ONTOLOGY_ROOT` export (이미 추가됨).

### 작업 7: 검증

1. `cargo test -p krw-agent-agent-image -p krw-agent-krw-contracts -p krw-agent-research-planner` → 통과
2. `KRW_ONTOLOGY_ROOT=... krw-agent image build` → ontology_catalog blob 포함 확인
3. 생성된 Markdown 내용 확인 (metric, 검색어 힌트 등 포함)
4. DeepSeek 서버 복구 후 실제 질문 실행 → evidence 확보/답변 품질 확인

## 제외
- `relations.yaml`, `language_signals.yaml` → AI 프롬프트에서 제외 (Rust/Python 내부용)
- objects.yaml의 id_pattern, hash 필드 → AI 불필요
- DeepSeek 503 → 대기 필요

## 기대 효과
- ontology YAML이 단일 진실의 원천
- `image build` 한 번이면 YAML → AI reference + Rust 검증 양쪽 자동 반영
- AI가 정확한 공시 용어로 검색, Rust가 값 수준 검증
- ontology에 metric/검색어 추가 시 빌드만으로 자동 동기화
